# Design System: BeanFeature Lab

## Overview

**Creative North Star: «Приборная рабочая станция / Instrument Workstation».** Это контракт для будущего интерфейса в режиме Operate, а не описание существующей реализации. Оболочка приложения тёмная, основная область научных данных светлая. Композиция разделяет компактную левую навигацию, центральное исследовательское поле и правую контекстную панель. Большая научная фигура, затем плотная таблица и проверяемый контекст должны составлять узнаваемое рабочее место исследователя. [Концепт 1](docs/design/VISUAL_CONCEPTS.md) задаёт направление; его PNG является композиционным ориентиром, а не буквальным контрактом каждого контрола и текста.

Приоритеты: данные, исследовательский workflow, читаемость, контролируемая плотность, сравнение и воспроизводимость. Из «Научного атласа» перенесены аккуратные аннотации фигуры, неопределённость и читаемость научных подписей. Из «Реестра и протокола» — происхождение данных и ясная цепочка `experiment configuration → run → result`. Декор не заменяет данные. Научные значения появляются только из реальных сохранённых результатов; до того показывать «Не рассчитано», «Не запускалось» или точное состояние отсутствия.

**Ключевые характеристики:**

- Desktop-first workspace с ограниченной глобальной навигацией и контекстной навигацией внутри раздела.
- Светлая центральная научная фигура занимает основную рабочую ширину; таблица поддерживает, а не вытесняет график.
- Правая панель показывает сведения о выбранном объекте и read-only параметры просмотра; состав зависит от контекста.
- Стандартные органы управления и обратная связь основаны на MUI; научные фигуры — Plotly; иконки — Tabler Icons.

**Правило разделения.** Анализ читает результаты и изменяет только вид/фильтры. Конфигурация эксперимента создаётся и изменяется в Experiment Runner. Classifier Demo применяет проверенную готовую модель и не выдаёт научных результатов.

## Colors

Основная тема: **тёмная оболочка + светлая рабочая область**. Это не две конкурирующие темы: тёмный слой обозначает постоянную инфраструктуру и навигацию, светлый — продолжительное чтение графиков, таблиц и форм. Поздняя полноценная dark theme возможна через те же семантические роли MUI и Plotly, с отдельной проверкой контраста; компоновка не меняется. Точные HEX и тональные шкалы пока не зафиксированы как реализованные токены: их следует закрепить в теме и проверить на реальном рендере при build.

| Семантическая роль | Применение |
|---|---|
| `app.shell`, `app.shellText` | Верхняя полоса, левая навигация и правая контекстная инфраструктура; контрастные подписи и active state. Правая панель может иметь отличимый более спокойный тон. |
| `workspace.background`, `workspace.surface` | Центральное поле, фигура, формы и таблицы; минимум дополнительных белых карточек. |
| `surface.elevated` | Menu, dialog, popover, временные overlay; не оборачивать каждую секцию. |
| `text.primary`, `text.secondary`, `divider` | Иерархия чтения и разделители на каждой соответствующей поверхности. |
| `action.primary`, `selection`, `focus` | Одно главное действие, выбранная строка/объект, заметная клавиатурная обводка. |
| `status.info`, `status.success`, `status.warning`, `status.error`, `status.neutral`, `status.notCalculated` | Вторичные сигналы состояния; текст и форма значка обязательны. |
| `plot.baseline`, `plot.uncertainty`, `plot.selected` | Научные линии/интервалы/выбор; не путать с цветом статуса или кнопки. |

Выбранная модель кодируется согласованной комбинацией цвета, формы маркера и, при необходимости, типа линии. Selector кодируется **отдельно**, преимущественно штрихом и подписью/фасетом: один оттенок не должен одновременно означать модель и selector. Если сочетаний слишком много для читаемой легенды, разделить представление на сопоставимые панели или ограничить видимые серии явным выбором. Палитру линий проверить на контраст и при нарушениях цветового восприятия; отбор, baseline и uncertainty должны различаться и при печати в оттенках серого. Не окрашивать весь интерфейс цветами моделей.

**Правило редкого акцента.** Яркий primary применяется к одному ведущему действию экрана («Создать эксперимент» в общем контексте или «Поставить в очередь» на Runner); фильтры и вторичные действия остаются нейтральными. На Feature Budget ссылка «Открыть Experiment Runner» в правой панели — вторичная, если основное действие уже есть в app bar.

## Typography

Основная гарнитура направления — профессиональная кириллическая sans **Golos Text** с системным sans fallback. Она используется для интерфейса, плотных таблиц и подписей Plotly. Шрифт поставляется через зафиксированный @fontsource/golos-text и локальные файлы сборки; системный fallback сохраняется. Числа таблиц и осей — tabular numerals. Для машинных значений — системный monospace, точечно: `RUN-000001`, hash, path, seed и идентификаторы; обычные тексты и научные подписи не переводить в mono.

| Роль | Характер и ориентир для build |
|---|---|
| Название приложения | Компактное, уверенное, без hero-типографики; помещается в shell. |
| Заголовок страницы | Один `h1` на экран, примерно 20–24 px, ясный вопрос или название задачи. |
| Заголовок секции / фигуры | Примерно 16–18 px, отделяет рабочие блоки, не доминирует над данными. |
| Основной текст | Примерно 14 px / 1.45–1.55, хорошо читаемая кириллица. |
| Таблица | Примерно 13–14 px, tabular numerals, длинные имена с tooltip или раскрытием вместо скрытой потери смысла. |
| Control label | Примерно 13–14 px, видимый текст рядом с полем; placeholder не является label. |
| Helper / metadata | Примерно 12–13 px, вторичный контраст без недоступной бледности. |
| Chart title / axis / legend | Примерно 15–16 / 12–13 px, согласованные с MUI; единицы и семантика `k` читаются без hover. |

Размеры — проектные диапазоны, а не уже существующие CSS-токены. Финальные значения проверяются на кириллице, длинных именах признаков, масштабировании текста и реальном Plotly render. Основной язык UI — русский. Общепринятые `Macro-F1`, `Accuracy`, `PCA`, `RFE`, `XGBoost`, `LightGBM`, `Random Forest` и `RUN-000001` сохраняются; не дублировать каждую подпись на двух языках.

## Layout

Desktop композиция: **верхняя application bar → компактная левая primary navigation → центральная рабочая область → правая contextual panel**. Центральная колонка получает оставшуюся ширину и сохраняет приоритет. Начальный проектный диапазон: nav около 200–224 px, inspector около 256–320 px, между областями тонкие структурные разделители; это ориентиры для responsive проверки, не жёсткая трёхколоночная сетка при любой ширине. Пространственный ритм компактный: внутренняя дистанция между тесно связанными элементами около 8 px, между группами около 16 px, между крупными областями около 24 px. Проверить реальные размеры в макете на 1280–1600 px и ноутбуке, прежде чем фиксировать токены.

Левое меню не растёт вместе с количеством отчётов: каждый пункт имеет читаемую текстовую подпись, Tabler-значок служит дополнением, а не заменой названия.

| Группа | Primary navigation |
|---|---|
| Исследование | Бюджет признаков · Эксперименты · Запуски |
| Анализ | Анализ признаков · Сравнение |
| Применение | Классификатор |
| Низ панели | Настройки проекта · Справка |

Overview доступен через название приложения/текущий проект и показывает состояние исследования списком последних runs и следующих действий, а не сеткой KPI. Experiment Runner — отдельный сценарий из «Создать эксперимент»/definition; он не становится новой длинной группой глобального меню. Внутри разделов используйте Tabs, короткое subnav и breadcrumbs для `configuration → run → result`, с явными названиями каждой сущности. Глобальный контекст app bar содержит **отдельные** project, dataset и selected run, ведущую команду и overflow; при отсутствии выбора: «Проект не выбран», «Датасет не загружен», «Запуск не выбран». Конфигурация не подменяет run; статус run и доступность результата показаны раздельно. Worker status доступен как вторичный системный контекст, если реально известен.

**Feature Budget**: (1) глобальный контекст; (2) заголовок и научный вопрос; (3) большой Plotly-график Macro-F1 против бюджета `k`; (4) связанный read-only inspector справа; (5) плотная supporting table под графиком. Toolbar над фигурой содержит только управление видом/фильтрами и ссылку к конфигурации; не помещать форму запуска и настройки модели в инспектор анализа. При отсутствии данных фигура сохраняет место и пишет «Не рассчитано», без декоративной кривой. Таблица показывает реальные selected features/fold records только после расчёта. Для PCA — отдельный вид/явный `budget_kind = pca_components`, ось «Число компонент PCA», предупреждение, что компоненты не являются `k` физических измерений; не объединять PCA в конкурс достаточности исходных признаков.

Правая панель зависит от выбранного объекта: для точки кривой — модель, selector, просмотренное `k`, interval и источники; для run — статус, dataset/hash, Git/environment и protocol; для отсутствующего выбора — короткий нейтральный prompt. Она продолжает тёмную инфраструктурную оболочку, но визуально тише центральной фигуры; содержимое группируется и не дублирует всю форму Runner. Длинные технические metadata — в disclosure/details. Не держать все поля одновременно. На Feature Budget selection и фильтр меняют представление, не scientific configuration.

При сужении окна сначала свернуть inspector в доступный по кнопке Drawer, затем сворачивать навигацию в rail/Drawer с текстовыми доступными названиями. Таблица имеет горизонтальную прокрутку и приоритет основных колонок; не обрезать идентификаторы без доступного полного значения. График сохраняет читаемый минимум и может использовать горизонтальную прокрутку/отдельный полноэкранный режим, а не сокращаться до KPI-card. На узком экране обеспечить чтение и отслеживание статуса, но не обещать полноценный mobile-first editor. Контекст проекта/датасета/run остаётся достижимым и при свернутой панели. Порог переключения определяется тестом содержания, а не единственным произвольным breakpoint.

## Elevation & Depth

Система плоская: тёмная оболочка отделена от светлого рабочего поля тоном и тонкими разделителями. Поверхность графика и таблица могут иметь лёгкую рамку или общий разделитель без вложенных cards. Тень допускается только для временных menu/dialog/drawer поверх контента; визуальную иерархию постоянных блоков создают положение, отступ и типографика. Нет glassmorphism, blur, больших мягких теней и декоративных градиентов. Motion минимален: короткое открытие панели, смена выбранного состояния и подлинный loading; `prefers-reduced-motion` сохраняет понятную смену состояния без перемещения.

## Shapes

Геометрия преимущественно прямоугольная, с умеренно скруглёнными MUI controls; у научной фигуры и таблицы границы сдержанные. Радиус не должен превращать строки таблицы в карточки. Не создавать собственные базовые формы ради идентичности. Tabler Icons — единая система пиктограмм, но каждый критичный статус содержит текст, а icon-only действия имеют доступное имя и tooltip. Размер интерактивной области проверяется отдельно от визуальной плотности: компактные строки не оправдывают труднодоступные кнопки.

## Components

**Стек:** MUI Core, MUI X Data Grid **Community**, Tabler Icons, Plotly. Для кнопок, input/select, forms, menus, dialogs, tabs, tooltips, navigation, alerts, drawers, progress и pagination использовать MUI. Тема настраивает роли цветов, плотность и типографику, а не создаёт собственный UI kit. Custom-код ограничен исследовательской композицией: Feature Budget figure, experiment/run context, аннотации и специализированные сравнения. Lucide, MUI Charts, MUI X Pro/Premium не применять.

### Plotly и научные фигуры

- Общие font family/weights с MUI; светлый фон фигуры, сдержанная сетка, тонкие axis lines и достаточные поля под русские оси/легенду. Условие `k=1…16` — диапазон оси, не заполненный результат. `Macro-F1` — y label; единицы, источник серии и тип бюджета видны без подсказки.
- Цвет + штрих + marker кодируют модель; selector кодируется отдельным каналом и явным текстом. Legend не перекрывает линии, доступна клавиатурой через сопровождающие controls/таблицу. Hover сообщает точные **сохранённые** значения, единицы, model, selector, dataset/run и uncertainty method при наличии; hover не является единственным способом прочитать результат.
- Отдельно обозначать model-specific baseline при `k=16`, область неопределённости, выбранную точку и научные аннотации. Margin `δ = 0.01` — **допустимая потеря относительно сопоставимого baseline той же модели на одинаковых outer folds**, а не универсальная горизонтальная линия на уровне `Macro-F1=0.01`. Показывать оценку достаточности только после сохранённых paired differences и утверждённого интервала, учитывающего зависимость repeated CV. Если интервал ещё не определён, пояснять ограничение вместо объявления «достаточного k».
- Выбранное пользователем `k` подписывать «Просматриваемое k», пока научный критерий не рассчитан. PCA получает отдельную подпись «Компонент PCA» и указание о потребности в исходных измерениях. Сохранять подписи и альтернативную таблицу значений/описание фигуры для доступности и экспорта; uncertainty указывать с методом, не рисовать вымышленные полосы.

### Таблицы, формы и workflow

- MUI X Data Grid Community: компактные строки и заголовки, tabular numerals, текстовые состояния, заметный keyboard focus, доступное полное значение при усечении. Сортировка и фильтр **по одному критерию**, пагинация в пределах Community (страница не более 100 строк). Не закладывать multi-sort/filter, pinning, grouping или Excel export как обязательные возможности. Пустая таблица объясняет причину; pagination не маскирует «нет расчёта» как «0 измеренных строк».
- Experiment configuration — описание **что запускать**; experiment run — конкретное исполнение; результат привязан к run и условиям. Реестр конфигураций показывает model, selector, budget, timestamps, число runs и переход к ним; создание копии конфигурации отдельным действием. Детали run показывают ID, status, UTC timestamps, definition, dataset version/hash, Git/dirty state, seed, environment, model/selector/budget, реальные metrics/resources, artifacts и errors. Частичный run явно неполон.
- Experiment Runner — отдельная ступенчатая форма: dataset → model → selector/representation → feature budget → CV → hyperparameter/search → resource measurements → review → queue/run. Перед очередью виден читаемый итог неизменяемого snapshot; причины disabled/invalid controls объясняются рядом с полями. Изменение исходной definition/clone не переписывает сохранённый run. Retry создаёт новый run.
- Feature Explorer переключает виды feature metadata, selection frequency/stability, correlation, importance и folds через Tabs/view switcher; Comparison допускает сопоставление models, selectors, `k`, runs и definitions при проверке сравнимости dataset/splits. Не помещать все представления на один экран и не присваивать бейдж «Победитель» без заранее определённого научного критерия.
- Classifier Demo — отдельный раздел «Применение», принимает валидные входные параметры для **уже обученной и зарегистрированной** модели; предсказание не является новым experiment run и не публикуется как результат CV. Если модели нет, показать это и путь к её получению.

### Статусы, пустота, загрузка и ошибка

| Внутренний enum | Русская метка | Дополнительная форма / доступное действие |
|---|---|---|
| `draft` | Черновик | Контурный маркер; редактирование конфигурации. |
| `queued` | В очереди | Часы; отмена, если разрешена. |
| `running` | Выполняется | Процесс/индикатор; текущая достоверная фаза, отмена. |
| `completed` | Завершён | Галочка; результаты и provenance. |
| `failed` | Ошибка | Значок ошибки; причина, технические детали и повтор как новый run. |
| `cancelled` | Отменён | Перечёркнутый маркер; запись и частичные результаты. |
| `not_calculated` | Не рассчитано | Тире/пустая фигура; причина и доступный следующий шаг. |

`draft` — состояние редактируемой конфигурации; исполняемый run начинается с `queued`. `not_calculated` относится к метрике/представлению, а не делает experiment run завершённым. Внутренний worker может иметь промежуточное `cancelling`; показывать «Отменяется», пока не получено `cancelled`. `not_run` для отсутствующего запуска отличается от `not_calculated` для неприменимой или ещё не полученной метрики. Цвет вторичен по отношению к тексту/значку/форме.

Пустые состояния различают: проект не выбран, датасет не загружен, нет configurations, запуск не выбран, результат не рассчитан, нет выбранных features, нечего сравнить, фильтры ничего не нашли, метрика недоступна. Каждое состояние содержит короткую причину и уместный следующий шаг, без фиктивных точек, процентов, признаков и матриц ошибок. Skeleton допустим для загрузки формы/таблицы, но визуально не должен выглядеть как истинный научный график. Если backend знает фазу или число завершённых folds, их можно показать с явным знаменателем; процент — только из реально определённого полного объёма работы. Иначе indeterminate progress и достоверная фаза, без «42%».

Ошибка говорит, что произошло, какой run затронут, что можно сделать; детали доступны по требованию. Не заменять её общим «Что-то пошло не так». Использовать MUI Alert/Progress/Dialog там, где они подходят, и не прятать ошибку за декоративной анимацией.

### Доступность и реализация состояний

Требуются семантические области страницы, логичный порядок фокуса, полная keyboard navigation (включая drawer, формы и таблицу), видимый `:focus-visible`, текстовые form labels, доступные tooltips, контраст не ниже применимого WCAG AA, достаточные hit areas, увеличенный текст без потери задач, reduced motion. Plotly дополняется текстовой подписью/таблицей значений и объяснением uncertainty; статус announce через уместные live regions без навязчивых повторов. Проверять фактическое поведение на устройствах и в браузере после реализации: этот документ не является сертификатом доступности.

## Do's and Don'ts

### Делать

- Делать scientific figure главным объектом Feature Budget, с короткими аннотациями, baseline и uncertainty только из реальных результатов.
- Показывать проверяемую цепочку configuration → run → result и dataset/Git/environment provenance; держать анализ read-only по отношению к определению эксперимента.
- Сохранять compact, scan-friendly MUI controls и таблицы при достаточном фокусе, контрасте и области взаимодействия.
- Показывать «Не рассчитано» и точные причины отсутствия вместо правдоподобных чисел; `k` исходных признаков отделять от числа компонент PCA.
- Conference Mode `/conference` использует отдельный восьмишаговый presentation layout с читаемыми научными фигурами, keyboard navigation и optional fullscreen. Семантика совпадает с workstation и verified PDF snapshot.

### Не делать

- Не строить generic AI/admin dashboard, KPI-card grid, hero section, крупные marketing metrics, card-in-card, большие радиусы, glassmorphism, blur, тени/градиенты и gradient text ради декора.
- Не добавлять сельскохозяйственные клише (листья, поля, фото фермы, семена как орнамент), роботизированную AI-иконографию, декоративный monospace или множество цветов без функционального смысла.
- Не использовать Lucide, MUI Charts, Pro/Premium возможности Data Grid и не писать собственные обычные buttons/inputs/dialogs/navigation, когда подходят MUI.
- Не рисовать fake curves, метрики, confusion matrices, выбранные признаки, лучший model, оптимальное `k` и фиктивный progress.
- Не редактировать исследовательскую конфигурацию на Feature Budget и не представлять Classifier Demo как Experiment Runner.
