# Доклад BeanFeature Lab: памятка выступающему

Эта памятка объясняет существующие восемь разделов `/conference`. Числа качества,
достаточные бюджеты и hashes читайте из текущего проверенного снимка, а не из памяти.
Новый снимок требует явного действия; повторная проверка не запускает обучение.

## Перед выступлением

1. Подключите Mac к питанию и интернету, оставьте крышку открытой. Запустите `make presentation` из корня совместимого checkout с восстановленными runtime-данными.
2. В другом терминале выполните `make presentation-status`: API/Web должны быть ready, worker — online, sleep — active, обе public probes — ready. Наличие tunnel process само по себе недостаточно.
3. Откройте `/conference`, дождитесь проверенного снимка. Проверьте фигуры и скачайте PDF на восьмом шаге заранее: локальная копия пригодится при сетевом сбое.
4. Выберите масштаб браузера, удобный на проекторе. ←/→ и Home/End переключают разделы; кнопки и меню работают отдельно. Fullscreen необязателен. При истечении снимка явно нажмите «Новый снимок» — текущий шаг сохранится.
5. После выступления выполните `make presentation-stop`. Named Tunnel управляется macOS и остаётся запущенным; процессы приложения и caffeinate этого сеанса завершаются.

## 1. Вопрос — около минуты

«Мы исследуем, как число исходных морфологических признаков влияет на качество
многоклассовой классификации фасоли. Бюджет k — число исходных измеряемых входов,
а качество — отдельная ось. Мы не измеряли экономию денег или времени получения
признаков и не называем меньшее k универсально оптимальным набором».

## 2. Данные

«Использован официальный UCI Dry Bean Dataset, ID 602: 13 611 наблюдений,
16 числовых признаков, 7 классов. Проверены официальный источник, SHA-256,
схема и отсутствие пропусков. Классы представлены неравномерно — распределение
видно в таблице. Canonical ARFF сохраняет AspectRation, roundness и DERMASON:
мы не исправляем эти официальные написания скрытно».

## 3. Протокол

«Оценивается вся процедура, включая настройку и выбор признаков: внешний
RepeatedStratifiedKFold 5 folds × 3 repeats; внутренний StratifiedKFold 4 folds
со shuffle. Общие frozen outer splits делают сравнения парными.
Scaler, selector и PCA обучаются только на соответствующем training fold.
Иначе информация внешнего теста попала бы в выбор признаков или настройку
и качество было бы завышено».

«Macro-F1 усредняет F1 классов с одинаковым весом, поэтому многочисленный класс
не доминирует как в Accuracy. Сохраняются также Accuracy, recall каждого класса,
confusion matrix и диагностический ROC AUC OvR, когда он доступен».

## 4. Бюджет

«Ось x — исходные признаки k, ось y — реальный средний Macro-F1 по внешним folds.
Цвет, форма markers и тип линии различают модели. Ромб на 16 — baseline без
отбора той же модели; MI при k=16 остаётся отдельным условием процедуры.
Мы показываем наблюдаемые точки и не достраиваем пропуски. Описательный fold SD
не является confidence interval независимых наблюдений».

Покажите резкое изменение на малых бюджетах и поведение около полного бюджета
только по видимым данным. Не обещайте монотонности и не объявляйте победителя
по наибольшей точке кривой.

## 5. Sufficient-k

«Потеря D = Macro-F1 baseline16 − Macro-F1 compact на одинаковом внешнем fold.
Практическая граница δ = 0.01 — абсолютная потеря Macro-F1, заданная заранее.
Для 15 сравнений внутри каждой модели используется one-sided Nadeau–Bengio
correction и Bonferroni α = 0.05/15. Corrected SE = sqrt((1/15 + 1/4) × s²(D));
верхняя граница = mean(D) + t(1−α, df=14) × corrected SE».

«Минимальное sufficient-k выводится только для полной совместимой семьи из 15
сравнений, если upper bound ≤ δ. Модели могут получить разные бюджеты из-за
разных paired losses и их вариации. Not sufficient означает, что достаточность
не установлена этим критерием; это не доказательство непригодности.
Поправка сделана внутри модели, не заявляется единая гарантия для любого
последующего выбора среди моделей и selectors».

## 6. Методы

«Полная основная кривая использует Mutual Information. ANOVA, RFE и tree
importance имеют заранее заданные comparator control points; разности средних
здесь описательные. L1 меняет фактическую sparsity между folds: C — параметр
регуляризации, не гарантированное k. PCA сокращает размерность представления,
но требует все 16 исходных измерений — компоненты не означают меньше физических
признаков. MLP входит в full-feature baseline; полной MLP budget curve в Core нет».

## 7. Ограничения

«Это internal repeated CV одного датасета. Независимая внешняя валидация не
проводилась. Нет основания обещать перенос на другую партию, камеру или регион.
Selector может выбирать разный состав между folds. Полные исторические rank
distributions и некоторые старые memory measurements отсутствуют; мы их не
восстанавливали вымышленно. Классификатор обучен на полном наборе для inference:
его прогноз — демонстрация применения, а не независимая оценка качества».

## 8. Источники

«Доклад и PDF используют один проверенный evidence snapshot: IDs, dataset/split
hashes, configuration fingerprints и hashes results позволяют проследить выводы.
Выбран самый ранний завершённый run каждого условия, не лучший по метрике.
Проверка выбранного artifact должна пройти; повреждение не заменяется другим run.
Отчёт доступен офлайн; воспроизводимость научного свидетельства не означает
byte-identical PDF или одинаковые runtime timings на другом компьютере».

Откройте один run, fold, экспорт или PDF для демонстрации цепочки происхождения.
Не нажимайте reproduce/enqueue во время публичного выступления.

## Частые вопросы комиссии

| Вопрос | Точный ответ |
|---|---|
| Почему не Accuracy? | Macro-F1 одинаково взвешивает классы при дисбалансе; Accuracy также сохранена. |
| Почему не обучить selector на всём dataset? | Тогда внешние тестовые наблюдения влияли бы на выбор признаков; это leakage. |
| Почему 15 folds нельзя считать независимыми? | Training sets перекрываются и CV повторяется; используется frozen Nadeau–Bengio correction, а не naive SD/√15. |
| Почему δ=0.01? | Практическая non-inferiority-style граница утверждена до анализа и не подобрана под результаты. |
| Sufficient-k — один лучший набор? | Нет. Это бюджет конкретной модели и MI-процедуры; selected sets могут различаться между folds. |
| PCA уменьшает число измерений? | Нет, только число компонент представления; все 16 raw inputs остаются необходимыми. |
| Какая модель лучшая? | Простое ранжирование outer-CV means не является отдельной честной процедурой выбора победителя. |
| Почему deployment Logistic Regression? | Это существующая проверенная inference-конфигурация с прозрачным локальным logit-разложением, не доказанный универсальный победитель. |
| Вероятность — гарантия правильности? | Нет. Это реальный predict_proba без отдельной calibration; не независимая accuracy и не гарантия. |
| Что означает объяснение? | Signed contributions в logit предсказанного класса после fitted scaling; это не causal/global importance и не разложение вероятности. |
| Есть независимые данные? | Нет; отсутствие external validation явно ограничивает перенос выводов. |
| Что делать без интернета? | Локальный Web/API продолжают работать при доступном Mac; заранее скачанный PDF читается без приложения. Публичный доступ требует сети и tunnel. |
| Как восстановить работу после поломки Mac? | Совместимый checkout, зависимости и проверенный runtime backup в новом каталоге. Нужна независимая off-device копия; Git содержит только код/протокол. |
